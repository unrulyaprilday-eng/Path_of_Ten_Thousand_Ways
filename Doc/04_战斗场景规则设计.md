# 战斗场景规则设计

> 本文档维护战斗界面、镜头、演出和时间规则。战斗在项目中的定位见 `03_核心玩法系统设计.md`，战斗原型与流派验证见 `05_流派成型与战斗原型.md`。

## 1. 战斗定位

当前战斗主定义：

> 牌库驱动的半实时斗法。

玩家虽然通过卡牌操作战斗，但屏幕感受应是“修士空中斗法”，而不是站桩卡牌对战，也不是固定技能栏 ARPG。

表现目标：

- 斗法持续演算，飞剑、敌人、功法和法器一直在动。
- 玩家低频打出手牌，像在关键时刻落子。
- 卡牌仍有牌库、抽牌、手牌、弃牌、洗牌和构筑随机性。
- 法器与功法主要提供规则和循环，少数主动件提供爆点。
- 灵气持续增长，玩家需要判断攒势、抢节奏或等待爆发窗口。

## 2. 半实时基础规则

### 2.1 时间流

战斗默认实时推进，不再保留固定分段回合结构。

| 系统 | 推进方式 |
| --- | --- |
| 灵气 | 按秒持续增长，有上限 |
| 抽牌 | 按时间、卡牌效果或功法效果触发 |
| 飞剑 | 按攻击间隔自动寻找目标并命中 |
| 敌人 | 按意图读条或技能冷却行动 |
| 法器 | 多数自动触发，少数主动件有冷却 |
| 功法 | 按条件、周期或状态阈值触发 |
| 状态 | 按触发间隔、命中次数或持续时间结算 |

### 2.2 灵气

灵气是出牌与少数主动法器的主要资源。

推荐 DEMO tuning：

| 参数 | 建议 |
| --- | ---: |
| 初始灵气 | 2 |
| 灵气上限 | 10 |
| 基础增长 | 1 / 秒 |
| 爆发期临时上限 | 可由功法或法器提高 |

灵气设计底线：

- 不使用固定回合恢复作为主规则。
- 高费牌应形成攒势感，而不是单纯拖慢节奏。
- 回灵牌、减费牌、灵气上限和灵气增长都可以成为构筑方向。

### 2.3 牌库与手牌

卡牌必须保留构筑卡牌的核心手感。

| 项目 | DEMO 建议 |
| --- | ---: |
| 初始手牌 | 4-5 |
| 手牌上限 | 7-8 |
| 抽牌间隔 | 3-5 秒或由功法决定 |
| 牌库为空 | 弃牌堆洗回牌库 |
| 强牌限制 | 可使用冷却、消耗、封存或高灵气费用 |

卡牌不是固定技能栏：

- 玩家不能永远稳定看到同一组技能按钮。
- 奖励、删除、升级、抽牌和弃牌必须影响战斗节奏。
- 同名强牌可以有短冷却，防止连续刷出后破坏演算，但冷却不能替代牌库循环。

### 2.4 卡牌、法器、功法分工

| 系统 | 默认交互方式 | 示例 |
| --- | --- | --- |
| 卡牌 | 主动打出，消耗灵气 | 召临时飞剑、斩击、回灵、护体 |
| 法器 | 多数自动触发，少数主动 | 剑匣响应召剑，护心镜免死，雷印主动引雷 |
| 功法 | 长期被动循环，少数神通入口 | 剑意达到阈值后强化齐射 |
| 神通 | 高费 / 高门槛主动爆发 | 万剑归宗、九霄雷落 |

## 3. 战斗界面布局

### 3.1 顶部区域

- 当前战斗层级与敌方名称。
- 敌方生命、护盾和关键状态。
- Boss 阶段提示。
- 敌方意图读条或技能倒计时。

敌人行动必须可预判。半实时不等于看不懂发生了什么。

### 3.2 中部战场区域

| 区域 | 位置 | 用途 |
| --- | --- | --- |
| 我方单位 | 左下区域 | 始终可见，展示御剑姿态和受击状态 |
| 敌方单位 | 右侧区域 | 始终可见，承接受击反馈 |
| 中央轨迹区 | 中间 | 飞剑、法术、投射物、连锁特效 |
| 风险提示区 | 敌我之间或敌方脚下 | Boss 技能预警、雷击落点、范围提示 |

我方单位表现规则：

- 持续待机动画。
- 轻微上下浮动。
- 根据当前构筑显示飞剑数量、剑意光痕或法器环绕。

### 3.3 底部操作区域

底部是卡牌决策区，不是技能栏。

- 当前手牌。
- 灵气条：当前值、上限、增长速度。
- 抽牌堆 / 弃牌堆数量。
- 当前选中卡牌的费用与可用状态。
- 少数主动法器与神通入口。

示例：

```text
灵气 6 / 10     +1.0 / 秒
牌库 12         弃牌 6
```

### 3.4 法器与功法显示

- 法器位可放在右下或手牌上方，不抢手牌主操作。
- 自动法器显示触发闪光、充能层或冷却圈。
- 主动法器数量必须少，避免变成第二技能栏。
- 功法显示更像当前循环状态：剑意阈值、神通充能、下一次强化条件。

## 4. 场景分层

| 层级 | 内容 | 运动速度 |
| --- | --- | --- |
| 远景层 | 云海、仙山、星空、雷云、秘境 | 约 0.1 倍 |
| 中景层 | 悬空平台、天空裂隙、山谷、矿井轮廓 | 约 0.3 倍 |
| 角色层 | 玩家、敌人 | 正常动画速度 |
| 特效层 | 飞剑、火焰、雷电、剑气、符灰 | 根据技能演出 |
| UI 风险层 | 读条、预警圈、意图提示 | 始终可读 |

角色层应保持清晰，特效层不能长期遮挡手牌、灵气和敌方意图。

## 5. 卡牌驱动演出规则

卡牌决定：

- 角色动作。
- 特效类型。
- 攻击轨迹。
- 命中反馈。
- 对自动演算系统的影响。

### 5.1 飞剑系

| 卡牌 | 演出流程 |
| --- | --- |
| 剑气斩 | 飞剑离体 -> 飞行攻击 -> 命中目标 -> 返回角色身边 |
| 引剑诀 | 指诀展开 -> 临时飞剑生成 -> 进入自动攻击队列 |
| 万剑诀 | 剑阵展开 -> 多把飞剑生成 -> 分批发射 -> 连续命中 |
| 万剑归宗 | 飞剑回环蓄势 -> 齐射 -> 屏幕震动与剑痕残留 |

### 5.2 雷 / 火 / 血等状态系

| 方向 | 演出重点 |
| --- | --- |
| 雷剑 | 点翠青雷痕、短促闪断、连锁跳击 |
| 火剑 | 符灰、余烬、宣纸焦边，不做满屏红火 |
| 血剑 | 朱砂细线、血玉裂纹、断锋残痕 |

### 5.3 防御与资源牌

防御和资源牌也必须有斗法反馈：

- 护体：角色周身出现旧玉 / 符箓 / 墨盾。
- 回灵：灵气条有可见涌入。
- 抽牌：符纸或玉简飞入手牌区。
- 减费：手牌边缘出现淡金流光。

## 6. 受击反馈规则

| 触发 | 表现 |
| --- | --- |
| 轻击 | 小幅后仰 |
| 重击 | 大幅后仰 |
| 暴击 | 击飞、屏幕震动 |
| 雷击 | 电流特效、短暂抽搐 |
| 剑气攻击 | 剑痕、切割光效 |
| Boss 压制 | 镜头轻压、背景雷云加重 |

受击反馈优先级高于待机动画，但不能打断关键 Boss 阶段演出。

## 7. 可读性规则

- 同屏特效过多时，弱化低优先级粒子。
- Boss 关键读条必须始终可见。
- 玩家当前灵气与手牌费用必须始终可读。
- 连锁爆发可以华丽，但结算来源需要在浮字、短日志或图标闪烁中可追溯。
- 强牌、主动法器和神通释放前，必须让玩家看懂资源是否足够、冷却是否结束。

## 8. 新手引导

新手引导不改变战斗主结构，只做信息提示。

允许：

- 第一次抽到关键牌时弹出极短提示。
- 首战用高亮提示灵气增长、费用、手牌和飞剑自动攻击。
- Boss 大招前给清晰读条与落点预警。

禁止：

- 把每场战斗切成固定分段回合。
- 让玩家必须点“结束”才能看到斗法发生。
- 把全部法器、功法、神通做成一排常驻技能按钮。

## 9. 战斗表现结论

最终镜头形式采用 2.5D 横版空中斗法。

核心特色：

- 持续御剑飞行。
- 多层动态背景。
- 牌库驱动决策。
- 半实时演算斗法。
- 强受击反馈。
- 修仙流派差异化表现。
