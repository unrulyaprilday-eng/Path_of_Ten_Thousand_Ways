# UI 美术与资源生产规范

> 本文档定义项目稳定的视觉语言、位图生产流程、文件规范与入库验收。具体资源缺口、当前制作单、来源和失败记录见 `11_资源制作单与开发记录.md`。

## 1. 视觉定位

核心方向：

```text
黑白冷墨修仙 + 克制点色 + 器物化 UI + 华丽斗法演出
```

- 大场景以黑、白、冷墨灰建立空间、气口和纵深，不把整屏染成米黄宣纸。
- 青绿用于灵力、飞剑核心、生机与可交互共鸣；朱砂用于危险、伤害、契印与关键确认；冷白雷光用于雷法、高能蓄力与爆发瞬间。
- 米白、旧纸色只用于卡牌、卷轴、题签、符纸等局部器物承载面，不作为全屏主色。
- 淡金只用于极少量品质边缘和器物细节，不与青绿、朱砂同时大面积争夺视觉焦点。
- “华丽”来自飞剑阵列、轨迹层次、墨迹扩散、雷光穿墨、朱砂契印、镜头节奏和角色动态，不来自堆叠边框、暗带和高纹理面板。

建议基础色：

| 职责 | 建议色 | 用法 |
| --- | --- | --- |
| 深墨 | `#101515` | 暗部、剪影、主要文字 |
| 冷墨灰 | `#394140` | 次级结构、雾层、禁用态 |
| 冷白 | `#EEF1ED` | 场景留白、亮部、雷光前的静态基底 |
| 局部纸色 | `#E8E2D5` | 卡牌、题签、卷轴等小面积器物 |
| 青绿 | `#3F9A8C` | 灵力、共鸣、锁定与生机 |
| 朱砂 | `#B94A3C` | 危险、伤害、契印与确认 |
| 雷光 | `#C8ECFF` | 雷法与高能瞬间，不作为常驻面板色 |
| 旧金 | `#B89A5A` | 极少量细边与品质提示 |

## 2. 风格边界

追求：

- 写意水墨、清楚轮廓、可读纵深和克制点染。
- 场景安静，角色与攻击方向一眼可辨，爆发时画面层次明显升级。
- 远看先识别人物、敌我关系、节点与主操作，近看再读取纸纹、墨痕、器物和符印细节。
- 商业化门面必须像游戏场景和可交互器物，不像网页表单、报表或通用暗色卡片集合。

禁止：

- 二次元萌系、Q 版、写实写真和 MMO 页游入口感。
- 大面积米黄洗色、持续黑底压色、紫黑或蓝黑厚涂、现代玻璃面板。
- 复杂背景叠复杂卡片、三层以上蒙版、横向黑带、重暗角和密集无意义装饰。
- 让生图模型生成中文正文、按钮字、数值、Logo 或需要准确阅读的图标。
- 用高亮几何条、临时方块或脏边抠图冒充正式角色部件和战斗承载物。

## 3. 分场景视觉规则

### 3.1 战斗

- 玩家位于左下，以三分之四背视角朝右上方攻击；普通敌人位于右上不同纵深位置，攻击轴约为斜向 45 度。
- 男性主角以黑白长发、墨色外袍和灰白内衬为主，青绿与朱砂只作局部灵力、玉饰、剑穗或契印。
- 玩家可脚踩适合承载的本命法器；没有承载类法器时，站在符合场景的断石、残梁、矿台或地面上。环绕、手持和承载法器必须按器物职责表现，不能强行把所有法器做成坐骑。
- 普通敌人支持 1-3 个目标并分布在前、中、后纵深；最终区域 Boss 位于画面正上方并形成压屏构图。
- 普通攻击和出牌保持稳定镜头；仅终极技、击杀和必要的 Boss 阶段转换允许短促推镜、停顿或构图变化。
- 顶部只承载生命、资源、敌方意图与阶段；中央保留角色、敌人和攻击演算空间；底部法诀区不得吞掉主角与脚下承载面。

### 3.2 地图与事件

- 地图从下向上推进，局部路径向左上、正上和右上分叉；以同一旧矿大境域逐幕深入，不做互不相干的菜单切页。
- 节点应读成场景中的地点、器物、人物或痕迹，而不是统一圆点和网页式路线卡。
- 奇遇、修炼、秘藏和剧情节点使用具体场景表达选择；场景负责氛围，选项与结果由 Unity 文本和交互组件表达。
- 当前 DEMO 不建立通用商店和货币界面，资源不得按固定灵石商店骨架生产。

### 3.3 卡牌、法诀与器物

- 法诀牌推荐比例 `5:7`，顶部为名称与消耗，中部为无字插画，下部为规则文本。
- 卡面插画不烘焙正文、数值和固定图标；可用、不可用、强化和锁定状态由程序统一表现。
- 本命法器、心法、剑诀和场景所得应有清楚的来源差异。器物图优先表现材质、轮廓和来历，不做脱离世界的通用物品槽。

## 4. 提示词模板

通用正向约束：

```text
Chinese ink wash xianxia game art, black white and cool charcoal ink,
clear silhouette and spatial depth, restrained jade green and cinnabar accents,
premium game-ready composition, elegant negative space, no beige full-screen wash
```

通用禁止项：

```text
no readable text, no Chinese characters, no logo, no UI labels,
no modern glass panel, no purple-black fantasy painting, no heavy vignette,
no horizontal black band, no muddy beige overlay
```

用途补充：

- UI 背景：明确要求低细节、低对比、可承载 Unity 文本，不生成卡框和面板。
- 透明角色：明确完整身体、朝向、主体占比、安全边、四角透明和自然墨散边缘。
- 战斗背景：明确角色安全区、攻击通道、HUD 安静区、远中近层职责和禁止角色/文字/UI。
- VFX：明确运动方向、持续时间、缩放范围、亮暗底合成和 alpha 衰减。
- Boss：明确屏幕占比、阶段可拆部位、压迫方向和可交互弱点，不使用“天劫化身”作为当前 DEMO 默认模板。

## 5. 生产流程

1. 先确认资源用途、页面职责、渲染层级和实际容器尺寸。
2. UI 先用色块、纯色面板和描边完成结构、阅读顺序与交互验证。
3. 布局成立后，优先生产当前 DEMO 最缺、最影响观感判断的正式资源。
4. 位图工具优先级为会话内 `image_gen` / `imagegen`，不可用、失败或不适用时再使用 `imagegen2`。
5. 生图硬性串行：一次只生成或编辑一张，完成目检并决定落库或拒收后，才开始下一张。
6. 生成后检查尺寸、构图、主体比例、文字污染、透明通道、暗亮底合成和实际 UI 缩放效果。
7. 合格资源同步落入展示目录和 `Resources` 目录；不合格资源不得进入 Unity 正式加载路径。
8. 记录工具、模型、提示词摘要、版本、处理方式、来源、路径和验收结果。

## 6. 目录与命名

正式资源按分类同时落库：

```text
UNITY/Assets/Art/<Category>/
UNITY/Assets/Resources/Art/<Category>/
```

常用分类：

```text
UI/
Scenes/
Characters/
Cards/
VFX/
Fonts/
Audio/
Music/
```

运行时 `Resources key` 不含扩展名，例如：

```text
Art/UI/ui_battle_target_lock_001
```

命名规则：

| 类型 | 格式 | 示例 |
| --- | --- | --- |
| UI | `ui_<页面或系统>_<用途>_<版本>` | `ui_battle_target_lock_001.png` |
| 场景 | `scene_<场景>_<层级>_<版本>` | `scene_battle_old_mine_far_001.png` |
| 角色 | `char_<身份>_<用途>_<版本>` | `char_player_sword_cultivator_battle_005.png` |
| Boss | `boss_<名称>_<用途>_<版本>` | `boss_xuantie_mine_sword_puppet_battle_001.png` |
| 卡面 | `card_art_<法诀>_<版本>` | `card_art_thunder_sword_001.png` |
| VFX | `vfx_<场景或流派>_<用途>_<版本>` | `vfx_battle_wanjian_fan_trail_001.png` |
| 图标 | `icon_<系统>_<用途>_<版本>` | `icon_battle_enemy_intent_001.png` |
| 音频 | `audio_<场景>_<用途>_<版本>` | `audio_battle_sword_hit_001.wav` |

约束：

- 文件名使用小写 ASCII、下划线和三位版本号，不能覆盖来源不同或构图不同的旧版本。
- `Art` 与 `Resources` 中同名位图内容保持一致；两个 Unity 路径各自保留正确 `.meta`，不得复制同一 GUID 的 meta 制造冲突。
- 新增或替换 Unity 资源后保留导入生成的 `.meta`，删除或改名必须与引用迁移在同一实现任务内完成。
- 构建脚本不得把带版本号的外部工具缓存路径写死进项目。

## 7. 格式与导入

- 完整背景使用 RGB/RGBA PNG；UI、角色和 VFX 透明资源使用真实 RGBA PNG。
- 透明资源四角透明，alpha bbox 除有意延伸到画外的边外，应与画布保留至少 8 px 安全区。
- 透明素材分别合成到亮纸底 `#EEE9DD` 和暗墨底 `#151817` 检查，不得出现绿边、白边、黑底、矩形羽化边或半透明脏灰。
- UI 导入使用 `Full Rect`、`Clamp`、关闭 Mip Map、打开 Alpha Is Transparency 与 sRGB；细描边资源不得使用明显破坏边缘的有损压缩。
- 需要九宫格的资源必须在制作单中记录安全区和建议 border；卡框、圆印和有明确比例的器物不默认九宫格拉伸。
- 装饰、烟雾、光晕、洗色、印记和连线默认关闭 `raycastTarget`。
- 字体必须可再分发并保留许可证；正式包不得只依赖开发机系统字体。

## 8. 失败与降级

- 遇到 502、524、远端断开、模型未开放或透明通道失败时，只允许一次有明确目标的降尺寸、降质量或确定性清理；仍失败即停止，不得并发碰运气。
- 透明接口不稳定时，可按用途改用普通 PNG、宣纸底器物图或纯绿幕后本地抠图；任何降级仍须通过透明边缘验收。
- 失败资源不得以半成品身份接入。缺图位置使用结构完整、信息可读的纯色/描边模块、旧资源或确定性本地合成回退。
- 本地合成和复用旧资源必须标注“降级资产”，不得冒充正式重绘。
- 每个失败项登记：用途、目标文件名、目标双路径、尺寸/格式、构图、安全区、禁止项、提示词摘要、工具/模型、失败原因、已尝试次数、当前回退和最终验收标准。
- 失败、拒收、来源与版本记录统一写入 `11_资源制作单与开发记录.md`。

## 9. 入库检查

- 用途、文件名、版本和分类明确。
- 双目录内容一致，`.meta` 存在且引用有效。
- 尺寸、色彩模式、透明安全区和压缩设置符合制作单。
- 无中文正文、按钮字、Logo 和错误伪文字污染。
- 在 1920x1080 与 1280x720 的实际容器中均保持轮廓、文字承载和交互可读性。
- 装饰层不阻挡交互，动态资源不遮挡角色、敌方意图和主操作。
- 来源、工具、模型、提示词摘要、处理方式、许可和最终路径已登记。
