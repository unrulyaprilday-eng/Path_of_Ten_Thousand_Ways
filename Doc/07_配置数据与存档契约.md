# 配置数据与存档契约

> 本文定义策划数据、运行时聚合和单局节点间存档的稳定契约。配置文件承载内容事实，玩法代码消费结构化数据，不以散落硬编码或文案字符串充当规则。

## 1. 配置真源

当前路径约定：

- 策划主表：`UNITY/Assets/Data/CSV/`
- 运行时聚合：`UNITY/Assets/Data/JSON/game_config.json`
- 聚合脚本：`UNITY/Assets/Data/generate_config_json.ps1`

CSV 是人工维护真源，JSON 是生成产物。不得同时手工修改 CSV 和 JSON 的同一数据。生成过程必须确定性输出，并在写入前完成结构与引用校验。

## 2. 通用字段规则

- 主键统一使用稳定的 `snake_case` ID。
- 已发布或进入存档的 ID 永不复用；重命名通过别名或迁移表处理。
- 百分比存裸值，例如 `12` 表示 `+12%`，字段名必须说明是百分比还是倍率。
- 布尔值只使用 `true / false`。
- 对接运行时枚举时保留 `runtime_enum`，但稳定 ID 仍是跨表和存档主键。
- 条件、效果、目标和来源使用结构化字段或明确引用，不把可执行规则塞进展示文案。
- 每份聚合配置记录 `schema_version` 与 `content_version`。
- 配置缺失、重复 ID、非法引用或类型错误必须生成明确校验失败，不静默回退到旧硬编码。

## 3. 核心数据职责

### 3.1 开局与角色

开局配置至少描述：

- 根脚与故事文本。
- 固定本命法器 `残剑胚`。
- 固定一阶心法 `旁支吐纳法` 及附带法诀。
- 初始剑诀 `残卷御剑式`。
- 可选择境域及其解锁状态。

旧 `journey_lines` 和启程信物池不再是当前 DEMO 开局候选真源；如为兼容保留，只能标记为旧字段，不能继续驱动新流程。

### 3.2 修行内容

内容配置按职责区分：

- `technique`：费用、目标、主动效果、冷却 / 封存、参悟阶段和来源。
- `heart_method`：心法层级、常驻规则、附带法诀、升级条件和分支。
- `innate_artifact`：自动攻击、冷却、炼形阶段、附性、承载表现引用。
- `artifact`：后获法器的触发条件、规则修改、槽位和代价。
- `realm`：灵力上限、初始灵力、获取系数、法诀通用威力系数。
- `foundation_rule`：筑基条件、道基规则、互斥关系和经历标记要求。

现有 `cards.csv` 可在迁移期继续作为法诀物理表名，但其前台语义统一为法诀。现有 `quality` 枚举可为兼容保留，不能继续派生通用彩色稀有度掉落。

### 3.3 地图与事件

地图配置至少描述：

- 境域、幕、纵深层、手工连线模板和种子生成版本。
- 节点类型、合法层位、可重复性、前置与排斥条件。
- 每幕固定故事职责、小 Boss 和最终 Boss 锚点。
- 节点池、事件池、修炼池、隐藏路线条件和 Boss 前修整约束。
- 经历标记的写入、读取和后续响应。

条件与效果必须引用稳定 ID。隐藏并不等于无规则：未向玩家公开的条件仍需能由校验器和存档完整重放。

### 3.4 多敌人遭遇

敌人定义与遭遇编组分离：

- 敌人表定义生命、意图池、状态抗性、威胁优先级和行为。
- 遭遇表定义 1-3 个成员、成员位置 ID、初始状态、变体和阶段生成物。
- Boss 主体、部位、契钉、甲片、核心与召唤物使用独立稳定目标 ID，并声明可锁定和伤害转移规则。
- 所有主动法诀、本命法器、状态和敌方行为使用统一目标查询接口。

旧的单一 `enemy_id` 遭遇结构只能作为迁移兼容，不得限制新战斗模型。

### 3.5 历练所得

原通用奖励权重改为“世界机会”配置：

- 来源场景或事件 ID。
- 可获得的法诀、心法、法器、参悟、炼形或筑基条件。
- 幕与纵深范围。
- 构筑标签、经历标记和前置条件。
- 一局唯一、保底、互斥和错过规则。
- 选择代价与后续影响。

旧 `reward_service_priorities`、通用三选一和商店商品池不得继续作为 DEMO 主流程真源。

## 4. 确定性与种子

- 单局创建时生成并保存根种子。
- 地图骨架、节点内容、事件候选和遭遇变体使用分域随机流，避免一个系统多抽一次随机数就改变整局后续。
- 存档同时保存生成算法版本和已经解析出的地图图结构。
- 读取存档时优先使用已解析图，不因配置顺序变化重新抽取旧节点。
- 同一配置版本、根种子和相同选择必须产生相同后续内容。

## 5. 节点间自动存档

单局流程采用固定节点间存档，不保存战斗中间状态。

### 5.1 保存时点

一个节点的结果、奖励、经历标记和新路径全部结算成功后，进入下一节点选择前，原子写入检查点。进入战斗后退出或异常中断，读取时回到该战斗开始前的最近节点间检查点。

不得在以下中间状态覆盖稳定检查点：

- 战斗进行中。
- 事件选择已点击但效果尚未全部结算。
- 地图已生成部分节点但合法性校验未完成。
- 筑基或 Boss 阶段转换尚未完成。

### 5.2 必存字段

| 分类 | 字段 |
| --- | --- |
| 版本 | 存档版本、配置 schema、content version、生成算法版本 |
| 随机 | 根种子、各分域随机流状态 |
| 地图 | 境域、当前幕、当前节点、已完成节点、可达节点、完整已解析图 |
| 角色 | 当前 / 最大气血、境界、灵力相关永久规则、道基 |
| 构筑 | 法诀及参悟状态、心法及层级、本命法器炼形、后获法器 |
| 世界 | 已消费唯一事件、经历标记、宿缘记录、隐藏路线状态 |
| 遭遇 | 已击败遭遇、小 Boss 结果、Boss 阶段前置；不保存战斗瞬时对象 |
| 解锁暂存 | 本局新见闻和待在结算时写入局外的数据 |

战斗中的手牌、抽牌计时、临时飞剑、敌人当前生命和瞬时状态不进入节点间检查点。

### 5.3 写入安全

- 先写临时文件并完成反序列化校验，再原子替换正式存档。
- 保留上一份可读检查点用于损坏恢复。
- 关键内容 ID 缺失时停止加载并报告具体 ID，不静默删除角色能力或剧情标记。
- 旧存档通过显式版本迁移；无迁移路径时说明不兼容，不尝试猜测字段。

## 6. 局外数据契约

局外只保存见闻和解锁：

- 已见根脚、心法、法诀、法器、道基、敌人、事件、隐藏节点和结局 ID。
- 击败记录、使用记录和一世摘要。
- 已解锁内容池、外观、情报和非数值传承道痕。
- 不保存永久攻击、生命、灵力、境界或通用货币加成。

单局结算时，将本局待提交见闻以幂等方式合入局外档案；重复结算同一 run ID 不能重复发放或重复计数。

## 7. 配置校验

每次生成聚合配置至少检查：

- ID 唯一且所有跨表引用存在。
- 开局恰有 1 个本命法器、1 部一阶心法和 2 门主动法诀。
- 心法附带法诀、本命炼形和道基规则不存在循环或缺失引用。
- 普通遭遇成员数为 1-3，Boss 部位与召唤物引用合法。
- 地图每个非终点节点至少有一条合法后路，不生成不可达 Boss 或无意义死路。
- 每幕固定故事节点和 Boss 锚点存在，筑基保底可达。
- 唯一事件和唯一能力不会因多个池重复投放。
- DEMO 配置不包含固定商店、通用货币依赖或天劫 Boss。
- 所有可写入存档的内容都有稳定 ID 和版本迁移策略。

## 8. 设计底线

- 不用文案解析、枚举序号或列表位置充当存档身份。
- 不允许 CSV 与 JSON 双重手工真源。
- 不因算法升级重新生成正在进行的旧地图。
- 不保存战斗中间状态，也不因中断跳过战斗代价。
- 不让兼容旧表继续决定新系统边界。
- 不以安全回退到硬编码掩盖配置错误。
