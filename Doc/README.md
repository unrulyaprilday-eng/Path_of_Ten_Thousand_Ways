# 修仙肉鸽卡牌 RPG 设计文档目录

## 当前执行锚点

当前 DEMO 不再追求先铺满多个根脚和多个首境，而是先完成一条可玩的纵切；首境页可以露出由信物牵引出的 2-3 个合理去处，但不做全地图自由选择。

前台推荐命名：

```text
开卷 -> 定根脚 -> 受信物 -> 入首境 -> 入场首战 -> 战后奖励 -> 择前路 -> 节点历练
```

执行结构：

```text
开卷（启动页）
↓
定根脚：入口完整，但首版只开放「世家旁支」
↓
受信物：同一根脚下出现 3 条启程线，每条线带一个启程信物
↓
入首境：从当前启程信物指向的 2-3 个合理首境中选择，优先打磨「旧矿地窟」等 P0 去处
↓
入场首战：确认首境后直接打一场短斗法，兑现“我踏入了哪里”
↓
战后奖励：拿到第一项补强后，再进入真正的择前路
↓
择前路：根据首战状态选择具体历练路线，推进三层节点
↓
天劫化身 / 阶段 Boss 检验
```

本轮统一口径：

- `携行之物` 不再作为前台页面名，前台统一称为 `启程信物`。
- 程序字段可以继续保留 `carry_item_*`，但 UI 文案优先显示为 `启程信物` 或 `临行一物`。
- 根脚不会直接锁死唯一信物；根脚决定启程线候选池。
- `启程线` 负责启动故事线、地图路线库和早期成长路径倾向；具体路线仍由后续节点选择决定。
- `启程信物` 承接故事线带出的启动信物库，具体信物负责本局 Build 起手倾向，并将首境候选收窄到 2-3 个有因果关系的大地图。
- `入首境` 不是全地图副本菜单，也不是信物定死唯一地图；它只展示当前信物合理指向的少量首境候选。`择前路` 不再抢在首战前做同等重量三选一；首境确认后先进入入场首战，首战奖励后再展开第一次正式择前路。
- 战斗不再按炉石式回合推进，也不保留固定分段回合。
- 当前战斗主定义为：`牌库驱动的半实时斗法`。灵气持续增长，飞剑 / 法器 / 功法持续演算，玩家用抽到的牌低频介入。

## 当前开发进度（2026-07-10）

本轮已经打通并验证以下纵切：

```text
入首境
↓
入场首战
↓
战后奖励三选一
↓
第一次择前路
↓
路线节点依次推进
↓
进入下一场战斗
```

已完成内容：

- 初始地图流程已经调整为 `起点 -> 入场首战 -> 首战所得 -> 旧矿岔路`。
- 入场首战胜利后会先生成结构化奖励三选一，奖励包含当前方向补强、通用生存 / 资源补强和高波动候选。
- 奖励领取后会真正写入牌组、功法、法器、遗珍、生命或灵气成长，再进入第一次正式 `择前路`。
- 第一层已配置 3 条旧矿路线：
  - `矿口余烬`：战斗 -> 奖励 -> 修炼，稳定消化首战所得。
  - `塌井深处`：战斗 -> 高价值奖励 -> 战斗，以连续压力换取更快成型。
  - `旧账暗室`：修炼 -> 整备 -> 战斗，先补规则组件再验证循环。
- 路线选择后会把对应节点序列插入本局地图，并从路线第一个节点继续推进；三条路线都能抵达已配置的下一场战斗。
- 入口遭遇与第一层路线敌人已经写入 `CSV`，并重新生成 `JSON` 运行配置；当前配置包含 9 条路线模板和 19 个敌人条目。
- 择前路卡会按节点内容优先使用旧矿或雷泽场景图，节点顺序、稳险节奏和收益重点作为主信息，不再表现成第二次流派选择。
- `UNITY/CompileCheck/Program.cs` 已加入首战后流程烟测，覆盖奖励数量与类型、旧矿三路线存在性、路线插入以及下一战敌人配置。

当前验证结果：

- `dotnet build UNITY\CompileCheck\CompileCheck.csproj`：`0 警告 / 0 错误`。
- `dotnet run --project UNITY\CompileCheck\CompileCheck.csproj`：`Post-opening battle flow smoke check passed.`
- `git diff --check`：通过；仅有项目当前允许的 CRLF 提示。

协作边界与下一步：

- 战斗节点本身的表现与逻辑仍由另一会话推进；本轮只完成并验证其前后的流程接口，没有覆盖或回退那部分改动。
- 下一步优先在 Unity 实际运行中检查 `战斗胜利 -> 奖励页 -> 择前路页 -> 路线首节点` 的转场、布局和点击手感。
- 随后继续打磨第一层路线中的奖励差异：`飞剑组件`、`塌井秘藏`、`暗室悟法 / 旧账整备` 应逐步形成不同奖励池，而不是长期共用同一套普通奖励表现。

## 当前废弃旧口径

- 不再把 `携行之物` 做成独立系统页；它是启程线中的 `启程信物`。
- 不再把择前路页做成二次选择 `万剑 / 雷 / 血`。
- 不再保留固定分段回合；教学也不使用这套旧骨架。
- 旧的开局视觉备忘与 DEMO 进度交接文档已合并进主文档并删除。
