# 核心玩法系统设计

> 本文档定义玩家一局游戏中的核心操作、系统边界和循环关系。项目定位见 `01_核心框架设计.md`，开局结构见 `26_开局结构与启程系统设计.md`，地图与节点细则见 `15_地图与节点体系.md`。

## 1. 核心玩法闭环

```text
首页整备传承道痕
↓
定根脚
↓
启程（携一物上路）
↓
进入首境与节点地图
↓
战斗或事件
↓
获得卡牌、功法、法器或资源
↓
强化当前构筑
↓
挑战阶段 Boss
↓
结算并回到局外成长
```

设计目标：

- 开局先给身份与出山理由。
- 中段通过节点和奖励逐步显化道途。
- 后段以 Boss 检验“这一世修成了什么道”。

## 2. 开局层

开局层负责建立这局的叙事和起势，不承担完整构筑。

### 2.1 传承道痕

局外整备项，提供轻偏置：

- 启程候选保证
- 少量路线或奖励权重修正
- 情报或重掷便利

### 2.2 根脚

根脚负责：

- 说明玩家从哪里来
- 提供轻量身份偏置
- 决定可见启程线池

### 2.3 启程线

启程线负责：

- 给出出山理由
- 指定携行之物
- 指定首境
- 给出起手偏向

启程线不等于最终道途，只是这局的第一推力。

## 3. 节点式肉鸽地图

节点地图负责提供：

- 路线选择
- 风险收益
- 流派成型速度
- 首境气质延续

节点类型建议保留：

| 节点 | 功能 |
| --- | --- |
| 普通战斗 | 基础构筑推进 |
| 精英 | 高风险高收益 |
| 事件 | 代价选择和奇遇 |
| 商店 | 修正构筑 |
| 修炼 | 恢复与强化 |
| 洞府 | 功法获取与悟道 |
| 秘藏 | 法器与高价值奖励 |
| Boss | 阶段检验 |

## 4. 玩家决策层

核心玩法应把玩家决策拆成四层：

| 层级 | 发生位置 | 主要决策 |
| --- | --- | --- |
| 整备决策 | 首页 | 装备哪枚传承道痕 |
| 身份决策 | 开局 | 接受当前根脚还是改命 |
| 启程决策 | 开局 | 选择哪条启程线、先去哪个首境 |
| 路线决策 | 地图 | 选择战斗、事件、商店或洞府路线 |
| 构筑决策 | 奖励与商店 | 选择卡牌、功法、法器、升级方向 |
| 战斗决策 | 战斗规划阶段 | 出牌顺序、资源分配、飞剑与法器触发时机 |

## 5. 道途系统

完整版本中，道途不再作为独立按钮直接裸选。

道途由以下信息共同显化：

- 根脚底色
- 启程线偏向
- 携行之物效果
- 首境奖励口味
- 已获得功法
- 已获得法器
- 已选卡牌标签

道途的作用仍然是：

- 控制单局方向
- 收束奖励池
- 让 Boss 检验有的放矢

## 6. 战斗系统边界

核心玩法层只定义战斗在整局中的职责：

- 卡牌提供低频关键决策。
- 飞剑提供高频自动输出。
- 功法提供长期循环。
- 法器提供规则强化与质变。
- 状态提供流派分叉和跨回合积累。

具体镜头、界面、时间规则和动作演出由 `04_战斗场景规则设计.md` 维护。

## 7. 奖励系统边界

前台奖励类型建议收口为四类：

1. 卡牌
2. 功法
3. 法器
4. 资源

奖励设计原则：

- 早期提供方向感。
- 中期补足循环组件。
- 后期提供质变法器、神通或规则修改。
- 奖励应和根脚、启程线、首境以及当前构筑共同相关。

## 8. 系统接口

| 系统 | 输入 | 输出 |
| --- | --- | --- |
| 开局 | 传承道痕、根脚池、启程线池 | 本局起势与首境 |
| 地图 | 首境模板、节点权重、玩家状态 | 下一节点选择 |
| 战斗 | 卡组、功法、法器、敌人配置 | 胜负、奖励、损耗 |
| 奖励 | 根脚、启程线、首境、当前构筑 | 卡牌 / 功法 / 法器候选 |
| 商店 | 货币、当前构筑、首境偏向 | 商品列表与刷新 |
| Boss | 层数、流派完成度、法器结构 | 阶段挑战与通关判断 |

## 9. 核心体验标准

一局体验成立时，玩家应能清楚感受到：

- 这一世我是谁、为何出山。
- 这次起手与上一次不一样。
- 第 1 层末到第 2 层初，我已经知道自己大概要修什么。
- 中期功法与法器开始一起运转。
- 后期出现明确爆发窗口。
- Boss 战检验了这一局修成的道。
