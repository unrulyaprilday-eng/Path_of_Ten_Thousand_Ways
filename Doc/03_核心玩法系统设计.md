# 核心玩法系统设计

> 本文档定义玩家一局游戏中的核心操作、系统边界和循环关系。项目定位见 `01_核心框架设计.md`，具体战斗演出见 `04_战斗场景规则设计.md`，流派成型节奏见 `05_流派成型与战斗原型.md`。

## 1. 核心玩法闭环

```text
选择初始方向
↓
进入节点地图
↓
战斗或事件
↓
获得卡牌、法宝、遗物或资源
↓
强化当前构筑
↓
挑战阶段 Boss
↓
结算并回到局外成长
```

设计目标：玩家每局都能从零散选择逐步收束到一个明确流派。

## 2. 节点式肉鸽地图

节点地图负责提供路线选择、风险收益和构筑节奏。

| 节点 | 功能 |
| --- | --- |
| 战斗 | 基础奖励来源，验证当前构筑 |
| 精英 | 高风险高收益，投放强遗物或核心卡 |
| 事件 | 提供资源交换、奇遇、代价选择 |
| 商店 | 消耗货币，补足构筑缺口 |
| 修炼 | 卡牌升级、恢复、临时强化 |
| Boss | 阶段检测和关卡推进 |

## 3. 玩家决策层

核心玩法应把玩家决策分成三层。

| 层级 | 发生位置 | 主要决策 |
| --- | --- | --- |
| 路线决策 | 地图 | 选择战斗、事件、商店或 Boss 路线 |
| 构筑决策 | 奖励与商店 | 选择卡牌、法宝、遗物、升级方向 |
| 战斗决策 | 战斗规划阶段 | 出牌顺序、资源分配、法宝触发时机 |

## 4. 道途系统

道途用于控制单局方向，避免奖励池过散。

首版建议道途：

- 剑道：飞剑、剑意、多段攻击、剑阵。
- 法道：元素、灵气、爆发术法、范围伤害。
- 器道：法宝、阵法、自动触发、复制联动。
- 魂道：召唤、献祭、亡魂、心魔控制。

道途选择后应影响：

- 奖励池权重。
- 商店商品权重。
- Boss 检测机制。
- 专属资源或状态出现频率。

## 5. 战斗系统边界

核心玩法层只定义战斗在整局中的作用：

- 战斗是构筑验证器。
- 飞剑提供持续输出和视觉爽点。
- 卡牌提供低频关键决策。
- 法宝提供规则改变和 Build 质变。
- 状态提供流派分叉和长期积累。

具体镜头、界面、时间规则和动作演出由 `04_战斗场景规则设计.md` 维护。

## 6. 奖励系统边界

战斗和事件奖励应优先服务流派成型。

奖励类型：

- 新卡牌：补充主动操作与战斗节奏。
- 功法：提供被动规则和流派核心。
- 法宝：改变战斗规则或自动触发逻辑。
- 遗物：提供局内永久强化。
- 资源：支持商店、升级、恢复和事件交换。

奖励设计原则：

- 早期提供方向选择。
- 中期补足联动组件。
- 后期提供质变组件或终结手段。

## 7. 系统接口

| 系统 | 输入 | 输出 |
| --- | --- | --- |
| 地图 | 当前层数、节点权重、玩家状态 | 下一节点选择 |
| 战斗 | 卡组、法宝、遗物、敌人配置 | 胜负、奖励、损耗 |
| 奖励 | 道途、已有构筑、稀有度权重 | 三选一或特殊奖励 |
| 商店 | 货币、道途、层数 | 商品列表 |
| Boss | 层数、流派完成度 | 阶段挑战与通关判断 |

## 8. 核心体验标准

一局体验成立时，玩家应能清楚感受到：

- 前期正在选择方向。
- 中期核心联动开始运转。
- 后期出现爆发或质变。
- Boss 战检验了这一局修成的道。
