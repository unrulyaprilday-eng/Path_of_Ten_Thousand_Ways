## 2. 核心可玩目标

项目的第一个成立标准是验证三件事：

1. 半即时卡牌战斗是否成立。
2. 从“定根脚 -> 受信物 -> 入首境 -> 节点历练”进入单局是否足够沉浸且清晰。
3. 卡牌、功法、法器、飞剑联动是否能在一局中形成明确道途并给出爆发爽点。

当前战斗口径更新为：

> 牌库驱动的半实时斗法。灵气持续增长，斗法持续演算，玩家用抽到的手牌低频介入。

## 4. 核心系统清单

### P0：必须先跑通

- 首页整备传承道痕。
- 定根脚与改命。
- 受信物页：根据根脚展示 3 条启程线，每条线绑定一个启程信物。
- 节点地图：首境、节点推进、路线选择。
- 战斗演算：灵气持续增长、敌人意图读条、飞剑自动攻击、法器 / 功法触发。
- 卡牌系统：牌库、抽牌、手牌、费用、出牌、弃牌、洗牌、基础冷却。
- 飞剑系统：自动攻击、属性、数量成长。
- 功法系统：主修、辅修、神通的最小闭环。
- 法器系统：起手补强、战中规则强化、掉落和替换。
- Boss 战：至少一个两阶段 Boss。

### P1：完善深度

- 根脚随机池与手选解锁。
- 传承道痕解锁与偏置规则。
- 启程线扩展与稀有线。
- 状态系统第一层：流血、灼烧、感电、剑意。
- 商店与基础经济。
- 图鉴记录开局选择、启程线和境域。

### P2：完整长线

- 稀有根脚与特殊命格。
- 多章节境域链。
- 宗门成长、道痕收藏、天机阁功能。
- 多流派、多 Boss、多世界层。

## 5. 奖励体系收口

玩家前台尽量只理解三类核心构筑件：

1. 卡牌
2. 功法
3. 法器

其中：

- 卡牌回答“这一回合怎么打”。
- 功法回答“这一局怎么修”。
- 法器回答“这一局靠什么器把规则推强”。

旧草案中的“法宝 / 遗物 / 道器”不再作为三套并列主系统同时暴露给玩家。

## 6. 系统验收标准

| 系统 | 成立标准 |
| --- | --- |
| 开局结构 | 玩家能清楚理解自己是谁、为何出山、先去哪里 |
| 节点地图 | 玩家能感到首境和启程线真的影响后续路线 |
| 卡牌 | 玩家能通过出牌改变半实时演算结果，且不会退化成固定技能栏 |
| 飞剑 | 不依赖频繁点击也能形成持续输出 |
| 功法 | 至少一门主修功法能明显定义一局方向 |
| 法器 | 至少一件法器能明显改变战斗规则 |
| 流派 | 一局中期能判断自己正在形成什么套路 |
| Boss | Boss 能检测玩家是否完成基础构筑 |

## 7. 开发优先级

1. 开局原型：定根脚、启程线、首境进入。
2. 战斗原型：灵气持续增长、牌库循环、飞剑、功法、法器联动。
3. 地图原型：首境节点图、首层掉落偏向、Boss。
4. 成型原型：功法 / 法器 / 状态 / 掉落保底。
5. 长期成长：传承道痕、根脚解锁、图鉴。

## 8. 当前不优先

- 多职业完整道统树。
- 大规模宗门经营。
- 大量 NPC 关系链。
- 商业化系统。
- 多世界层长线剧情。

这些内容保留在完整设计中，但不作为当前第一阶段的硬前置。
