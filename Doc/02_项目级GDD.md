## 2. 可玩版本目标

MVP 的目标是验证三件事：

1. 半即时卡牌战斗是否成立。
2. 单局内是否能形成明确流派。
3. 法宝、飞剑、功法联动是否能产生爽点。

## 3. MVP 内容范围

| 模块 | MVP 数量 | 验证目标 |
| --- | ---: | --- |
| 可选道途 | 1 个 | 优先验证剑修或雷修 |
| 卡牌 | 30 张 | 覆盖攻击、资源、联动、终结 |
| 遗物 | 10 个 | 验证局内规则强化 |
| 法宝 | 4 个 | 验证主动、被动、成长、复制类效果 |
| 地图 | 1 张 | 覆盖战斗、事件、商店、Boss |
| Boss | 1 个 | 验证流派成型与终局压力 |

## 4. 核心系统清单

### P0：必须先跑通

- 战斗回合：规划阶段、执行阶段、结算阶段。
- 卡牌系统：抽牌、费用、出牌、弃牌、基础效果。
- 飞剑系统：自动攻击、属性、数量成长。
- 法宝系统：主动触发、被动联动、冷却或资源消耗。
- 奖励系统：战斗后三选一、遗物获取、卡牌升级。
- Boss 战：至少一个两阶段 Boss。

### P1：完善构筑深度

- 道途选择与掉落权重。
- 功法被动与流派核心卡。
- 状态系统第一层：流血、中毒、灼烧、感电。
- 商店与基础经济。
- 局内结算与基础局外收益。

### P2：长期扩展

- 境界突破。
- 宗门成长。
- 图鉴、成就、Ascension 难度。
- 多流派、多地图、多 Boss。

## 5. 战斗与表现规格

战斗采用半即时卡牌制：

- 规划阶段：约 15 秒。
- 执行阶段：约 5 秒。
- 超时自动进入执行。

镜头与演出规格以 `04_战斗场景规则设计.md` 为准。若 `04` 与本文冲突，以 `04` 为战斗表现最终来源。

## 6. 系统验收标准

| 系统 | MVP 验收点 |
| --- | --- |
| 卡牌 | 玩家能通过出牌改变执行阶段结果 |
| 飞剑 | 不依赖频繁点击也能形成持续输出 |
| 法宝 | 至少一个法宝能明显改变战斗规则 |
| 流派 | 一局中期能判断自己正在形成什么套路 |
| Boss | Boss 能检测玩家是否完成基础构筑 |
| 奖励 | 每次战斗后选择都影响后续路线 |

## 7. 开发优先级

1. 战斗原型：先完成最小战斗闭环。
2. 构筑原型：加入奖励、遗物、流派权重。
3. 关卡原型：加入节点地图和 Boss。
4. 长期成长：加入境界、图鉴和局外资源。
5. 资源替换：按 `21-22` 生产规范替换正式素材。

## 8. 不在 MVP 内

- 多角色完整养成。
- 完整宗门建设。
- NPC 关系系统。
- 商业化系统。
- DLC 内容。
- 大规模装备词条库。

这些内容已在 `01_核心框架设计.md` 中作为长期方向保留，MVP 阶段不进入主线开发。
