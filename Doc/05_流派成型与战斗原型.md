# 流派成型与战斗原型

> 本文档关注“玩家如何在一局内从身份与启程走到道途成形”。战斗场景和演出规则见 `04_战斗场景规则设计.md`，开局结构见 `26_开局结构与启程系统设计.md`。

## 1. 原型验证目标

首个战斗原型需要验证：

- 玩家能通过低频出牌影响高频自动战斗。
- 功法、法器、飞剑之间能形成可理解的联动。
- 启程线能给出明确起势，但不锁死中期选择。
- 中期前后能看出清晰道途。
- 后期能出现清屏、秒 Boss 或规则质变。

## 2. 战斗控制结构

| 控制层 | 频率 | 内容 |
| --- | --- | --- |
| 玩家决策层 | 低频 | 出牌、激活法器、释放神通、选择节奏 |
| 自动执行层 | 高频 | 飞剑攻击、Buff 触发、法器联动、持续伤害 |
| 构筑反馈层 | 跨战斗时间 / 跨节点 | 状态积累、资源成长、显化值提高、奖励方向变化 |

当前战斗原型不采用固定分段回合，而采用半实时演算：

- 灵气持续增长。
- 飞剑、敌人、功法和法器持续行动。
- 玩家用抽到的牌在关键时机介入。
- 卡牌仍然有牌库、手牌、弃牌和洗牌，不是固定技能栏。

## 3. 三阶段构筑结构

### 3.1 起势期：开局至第 1 层

目标：让玩家知道自己“为什么这样起手”。

这一阶段的构筑来源：

- 根脚底色
- 传承道痕轻偏置
- 启程线与启程信物
- 首境节点模板

成立标志：

- 玩家能说清自己为何从这条路开始。
- 第一层奖励已经开始向某个标签倾斜。
- 但玩家仍能根据功法或法器候选转向。

### 3.2 成型期：第 2-3 层

目标：构筑系统开始稳定运转。

主要投放：

- 核心功法
- 引擎型法器
- 状态资源循环
- 卡牌升级与压缩

成型标志：

- 飞剑数量、频率或效果明显增长。
- 感电、剑意、流血等状态开始自洽。
- 玩家能说清“我这局在玩什么”。

### 3.3 爆发期：第 3 层末至 Boss

目标：构筑完成并出现质变。

主要投放：

- 神通
- 爆发型法器
- 规则型法器
- 高品质补强

爆发示例：

- 万剑齐发
- 雷剑连锁清屏
- 压血后斩杀 Boss

## 4. 流派形成机制

### 4.1 起势来源

玩家并非在开局直接“选择道途”，而是从以下因素中逐步显化：

| 来源 | 作用 |
| --- | --- |
| 根脚 | 给出身份与轻偏置 |
| 传承道痕 | 给出局外轻准备 |
| 启程线 | 给出这一世的起手故事 |
| 启程信物 | 给出本局第一推力 |
| 首境 | 给出第一层口味 |
| 功法 | 负责真正定方向 |
| 法器 | 放大方向并推动质变 |

### 4.2 显化值

系统为每条候选道途维护显化值。

设计要求：

- 开局只能起势，不能直接定道。
- 功法应是最强的定道来源。
- 法器应是最强的放大来源。

### 4.3 同系倍率

同系组件达到数量阈值后触发新的规则。

| 条件 | 示例效果 |
| --- | --- |
| 3 个飞剑组件 | 飞剑数量 +1 |
| 5 个飞剑组件 | 开启剑阵 |
| 3 个感电组件 | 感电触发追加雷击 |
| 5 个流血组件 | 低血时追加斩杀收益 |

## 5. Boss 验证机制

| Boss 阶段 | 验证目标 |
| --- | --- |
| 中 Boss：妖王 | 是否有基础输出循环 |
| 后 Boss：魔尊 | 是否形成完整联动 |
| 终 Boss：天劫 | 是否达到流派上限并能承受压力 |

Boss 不只是数值墙，而是流派检测器。

## 6. 成型失败保护

为了避免玩家整局拿不到核心组件，需要加入保护机制：

- 连续两层未出现当前显化方向的核心奖励时，提高相关权重。
- 商店固定刷新至少一个当前显化方向的商品。
- Boss 前提供一次修炼或补强节点。
- 事件可用代价换取核心方向组件。

## 7. 核心体验闭环

```text
定根脚
↓
选择启程线与启程信物
↓
进入首境
↓
功法与法器逐步成型
↓
道途显化
↓
进入爆发期
↓
击败 Boss
↓
完成一世修行
```

设计底线：

- 每局必须有方向。
- 开局必须有来历。
- 中期必须能运转。
- 后期必须有爆发。
