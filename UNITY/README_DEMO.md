## 目标纵切

当前目标是一条约 30-40 分钟的旧矿三幕旅程：

- 根脚与所携合并为沉浸式开局，地图选择单独保留。
- 每幕实际走过 6-8 个以上节点，地图自下向上，手工骨架加种子变化。
- 无通用货币和固定商店；法诀、心法、法器与筑基在具体故事场景中获得。
- 开局为残剑胚自动攻击、旁支吐纳法附带心诀和一门初始剑诀。
- 支持 1-3 名敌人、自动攻击与点击锁定。
- 普通战玩家左下朝右上，最终 Boss `玄铁镇矿剑傀` 位于正上方压屏。
- 第二幕末在故事中完成炼气到筑基，第三幕验证道基规则和完整构筑。

## 工程与运行

- 工程目录：`UNITY/`
- 项目锁定版本：读取 `ProjectSettings/ProjectVersion.txt`；当前为 `6000.3.17f1`。
- 当前环境编辑器入口：`D:\Unity Hub\Editor\Unity.exe`。
- 打开工程后进入任意测试场景并点击 Play；`DemoBootstrap` 会创建运行时控制器和 Canvas UI。
- 不同时启动两个指向同一工程的 Unity Editor。

当前仍以运行时拼装 UI 为主。新页面应先建立真实游戏空间、信息层级和交互，再接入正式资源；不能继续把程序矩形叠成临时面板，也不能让旧资源规格反向限制新战斗构图。

## 配置

- 策划表：`Assets/Data/CSV/`
- 运行时聚合：`Assets/Data/JSON/game_config.json`
- 生成脚本：`Assets/Data/generate_config_json.ps1`
- 配置说明：[`Assets/Data/README_CONFIG.md`](Assets/Data/README_CONFIG.md)

CSV 是人工维护真源，JSON 是生成产物。新数据结构、兼容边界和节点间存档契约以 `Doc/07` 与实施计划的阶段 A/B 为准。

## 常规验证

纯代码或配置改动至少执行：

```powershell
dotnet build UNITY\CompileCheck\CompileCheck.csproj
dotnet run --project UNITY\CompileCheck\CompileCheck.csproj
git diff --check
```

UI 结构、状态机、Resources、场景或序列化改动必须补 Unity 实际导入/运行、连续流程截图、`1920x1080` 与 `1280x720` 双分辨率及逐图目检。完整标准见 [`09_开发验证规范.md`](../Doc/09_开发验证规范.md)。

## 资源规则

- 视觉方向为黑白冷墨，青绿、朱砂和冷白雷光克制点色；米白只用于局部纸张器物。
- 位图按 `imagegen -> imagegen2` 顺序串行单张生成，生成、验收、落库或拒收完成后才能开始下一张。
- 合格资源同时进入 `Assets/Art/<Category>/` 和 `Assets/Resources/Art/<Category>/`，文件名与运行时 key 可追溯。
- 旧批次提示词和携行/首境/天劫资源清单已被整合并停止执行。当前制作顺序、精确文件名、尺寸、失败记录与回退见 `Doc/11`。
